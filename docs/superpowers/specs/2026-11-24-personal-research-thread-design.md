# 个人研读线索设计

- 日期：2026-11-24
- 状态：设计已获用户确认，尚未实施
- 代码基线：`e732786`
- 范围：只在现有页面与功能内增加“个人研读线索”，不新增页面、不接 AI、不改史料正文、不动后端。

## 1. 目标

把用户已经留下的研读行为串成一条可继续追索的问题链，让“读过、选过、答错、亲历”不再只是统计数字，而成为可回看的个人证据。

每条线索由三部分组成：

1. 一个研究问题。
2. 三个证据槽。
3. 一个下一步行动。

第一版提供三条线索：

- `yitiaobian`：复用现有一条鞭法专题。
- `tumubao`：复用土木堡、于谦与北京保卫战内容。
- `chongzhen`：复用崇祯、煤山前夜与人物对话内容。

## 2. 非目标

- 不新增独立页面或顶级导航。
- 不新增后端接口、模型调用或服务器存储。
- 不新增 localStorage key；数据继续放在现有 `shimais-daming:progress:v1` 中。
- 不改变现有史料、章节、亲历剧本、题目和人物设定。
- 不把线索进度表述为“掌握度”或“历史定论”。
- 不自动开始线索，不在只读浏览时写入进度。

## 3. 内容边界

线索定义中的标题优先复用已有定版标题：

- 一条鞭法：`一条鞭法：从赋役合并到农户成本`
- 土木堡：`土木堡与北京保卫战`
- 崇祯：`崇祯`

三条“研究问题”属于新增文案，必须由用户定版后录入。文案到位前，线索卡只显示上述现有标题与步骤目标，不生成新的史实判断或问句。

所有新增界面标签同样遵循逐字文案规则；未经用户确认，不自行润色为新的历史叙述。

## 4. 数据模型

在现有 `progress` 对象下增加 `research` 字段：

```js
research: {
  activeId: "yitiaobian",
  byId: {
    yitiaobian: {
      evidence: ["event:e1581", "story:q1581"],
      updatedAt: 1690000000000
    }
  }
}
```

约束：

- `activeId` 必须是已定义的线索 ID。
- `byId` 只保存用户明确开始过的线索。
- `evidence` 只保存合法、去重的证据 key。
- `updatedAt` 使用 `Date.now()`，仅用于同设备内的线索排序。
- 不保存聊天正文、搜索正文或其他敏感内容。

## 5. 证据映射

证据 key 统一使用 `类型:ID`，由 `data.js` 中的线索定义集中映射。

| 线索 | 证据槽一 | 证据槽二 | 证据槽三 |
| --- | --- | --- | --- |
| `yitiaobian` | `event:e1581` | `card:i3`，或回看 `zhangjuzheng/c4`，或完成专题题 | `story:q1581` |
| `tumubao` | `event:e1449` | `decision:d1449`，或 `card:p3`，或进入 `chapter:tumubao` | `story:q1449` |
| `chongzhen` | `event:e1644` | `story:q1644` | `chat:chongzhen`，或 `card:p6`，或进入 `chapter:chongzhen` |

通用规则：

- 同一槽接受多个替代证据，但任意一个有效证据只点亮该槽一次。
- 错题只有在用户点击“回看这条史料”后才记为 `review:<sourceId>`，仅答错不直接点亮。
- 重复触发不重复写入；界面可提示“已记录”。
- 三个槽全部点亮后，线索进入完成态，下一步改为“回看证据链 / 换一条线索”。

## 6. 开始、切换与恢复

- 画像页未开始任何线索时，显示三张紧凑线索卡，用户点击“开始追索”后才创建 `research` 数据。
- 用户切换线索时，旧线索证据保留，新线索从自己的 `byId` 恢复。
- 刷新页面后按 `activeId` 恢复当前线索。
- 首页“继续上次”保持原有 `lastRead` 行为；若存在进行中的线索，在其下增加次要入口“继续研读线索”。
- 旧存档没有 `research` 字段时安全视为未开始，不自动迁移或写入。

## 7. 界面与交互

### 7.1 画像页

在“研读足迹”上方新增“研读线索”区：

- 未开始：三张单列或自适应线索卡，显示现有标题、相关足迹和开始按钮。
- 进行中：研究问题标题、三个证据槽、当前下一步、切换线索入口。
- 完成态：显示“已形成第一轮判断”，提供回看与换线索操作。
- 证据槽使用现有发丝线连接；已取证用黄铜小点，未取证保持空心。

### 7.2 全站轻量回声

有效取证后，在页面底部显示一条短提示：

> 已为「一条鞭法」线索取证 · 读机制 → 查看线索

规则：

- 不弹窗、不强制跳转、不打断阅读。
- 同一证据重复触发只提示“已记录”。
- localStorage 写入失败时不显示“已记录”。

### 7.3 检索标记

检索结果中，若某条材料可以补全当前线索的某个证据槽，只在标题旁增加一个小标记。标记不改变原卡片结构，不增加新色相。

### 7.4 响应式与动效

- 390px 下证据链改为纵向，线索卡单列。
- 所有新增区域不得产生文档级横向溢出。
- 动画沿用现有淡入与 stagger，不新增动效体系。
- 遵循 `prefers-reduced-motion`。

## 8. 数据流

1. 用户明确开始某条线索。
2. 现有动作入口调用统一的 `recordThreadEvidence(evidenceKey)`。
3. 函数读取当前 `progress`，校验 `activeId`、线索定义和证据映射。
4. 合法证据写入 `research.byId[activeId].evidence` 并去重。
5. 写入成功后才显示回声提示。
6. 画像页只读取 `research` 进行渲染，不自动选择或启动线索。

## 9. 错误处理

- `research` 不是对象、`activeId` 未知、`byId` 损坏：忽略对应字段，按未开始状态渲染。
- 证据 key 不在映射表中：不写入、不提示。
- 深链目标失效：内容测试直接失败，不允许带失效链接发布。
- localStorage 配额或隐私模式写入失败：保持只读体验，不显示假保存。
- 不合法数据不得导致决策、画像、检索或其他页面白屏。

## 10. 测试与验收

### 10.1 内容测试

- 三条线索定义完整，ID 唯一。
- 所有深链目标存在于现有数据中。
- 证据映射只引用合法的事件、卡片、决策、亲历、人物、章节或来源 ID。
- 新增 `research` 字段不改变既有史料、题目、剧本和搜索索引。

### 10.2 浏览器回归

1. 未开始线索时，画像页不产生任何 localStorage 写入。
2. 开始线索后存储结构正确。
3. 事件、决策、亲历、错题回看分别点亮对应证据槽。
4. 重复动作不重复计数。
5. 三槽集齐后进入完成态。
6. 切换线索保留各自证据。
7. 刷新后恢复当前线索。
8. 损坏的 `research` 数据不会白屏。
9. 检索标记只出现在匹配材料上。
10. 写入失败时不显示“已记录”。
11. 390px 无文档级横向溢出。
12. 原有内容测试、浏览器回归与后端测试保持全绿。

## 11. 视觉与内容红线

- 沿用玄黑底、冷纸白正文、灰褐次级文字。
- 仅使用黄铜与沉宫墙红作为小面积点缀。
- 分割使用中性发丝线，不增加彩色描边或渐变条。
- 保持直角、大留黑、宋体衬线标题与无衬线正文。
- 不修改既有定版文案，不新增未经用户确认的史实表述。
- 不改变访问范围，不自动发布。

## 12. 实施顺序

1. 增加线索定义、证据映射与统一记录函数。
2. 接入现有事件、决策、亲历、错题回看、人物对话和章节入口。
3. 完成画像页、首页次要入口、底部回声与检索标记。
4. 补齐内容测试和浏览器回归，执行全套验收。

实施前需单独确认三条研究问题文案；技术实现不得先于文案确认填入自拟史实问句。
